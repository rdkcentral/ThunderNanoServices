# Per-Callsign Registration Usage Guide

`TestPerCallsignRegistrationIShell` and `TestPerCallsignRegistrationIController` validate Thunder's per-callsign lifecycle notification filtering through `IShell` and `IController`.

Its JSON-RPC controls invoke the production C++ API internally:

```cpp
_service->Register(this, callsign);
```

The controls are a QA driver for `IShell`; they are not a JSON-RPC version of `IShell::Register`.

> **Important:** A JSON `callsign` value of `null` creates a global subscription. The observer receives lifecycle notifications for every plugin and an initial notification snapshot for plugins that are already active. Use a non-empty callsign to filter notifications to one plugin.

## Build and Install

The QA interface is generated by ThunderInterfaces. Install its generated headers before building ThunderNanoServices:

```bash
cmake -G Ninja -S ThunderInterfaces -B build/ThunderInterfaces \
  -DCMAKE_INSTALL_PREFIX="$PWD/install"
cmake --build build/ThunderInterfaces --target install -j"$(nproc)"

cmake -G Ninja -S ThunderNanoServices -B build/ThunderNanoServices \
  -DCMAKE_INSTALL_PREFIX="$PWD/install" \
  -DPLUGIN_TESTPERCALLSIGNREGISTRATION_ISHELL=ON
cmake --build build/ThunderNanoServices --target install -j"$(nproc)"
```

The test plugin starts deactivated by default. Start Thunder, then activate the observer:

```bash
./install/bin/Thunder -f -c install/etc/Thunder/config.json

curl -s -X POST http://127.0.0.1:55555/jsonrpc \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":1,"method":"Controller.1.activate","params":{"callsign":"TestPerCallsignRegistrationIShell"}}'
```

Keep the observer active for the entire test. Its `Deinitialize()` method removes all monitor registrations.

## Unit Tests

An optional in-process GTest suite is available in `ThunderNanoServices/tests/TestPerCallsignRegistration/IShell/tests`. Enable it together with the plugin:

```bash
cmake -G Ninja -S ThunderNanoServices -B build/ThunderNanoServices \
  -DCMAKE_INSTALL_PREFIX="$PWD/install" \
  -DPLUGIN_TESTPERCALLSIGNREGISTRATION_ISHELL=ON \
  -DTESTPERCALLSIGNREGISTRATION_ISHELL_TESTS=ON
cmake --build build/ThunderNanoServices --target PerCallsignRegistrationIShellTests -j"$(nproc)"
ctest --test-dir build/ThunderNanoServices --output-on-failure \
  -R PerCallsignRegistrationIShellTests
```

The suite requires GTest and `thunder_test_support`. Build and install Thunder with `-DENABLE_TEST_RUNTIME=ON` first. If either dependency is unavailable, CMake skips the test target.

The test runtime loads three separately managed instances of the same test-plugin library:

| Callsign | Role |
|---|---|
| `Observer` | Registers the per-callsign notification sink and exposes the QA interface. |
| `PluginA` | The selected callsign. |
| `PluginB` | The control callsign that must be filtered out. |

It verifies the `PluginA` active-state snapshot, confirms that a `PluginB` deactivation is not delivered, then verifies that a `PluginA` deactivation is delivered exactly once.

The corresponding IController suite is enabled independently:

```bash
cmake -G Ninja -S ThunderNanoServices -B build/ThunderNanoServices \
  -DCMAKE_INSTALL_PREFIX="$PWD/install" \
  -DPLUGIN_TESTPERCALLSIGNREGISTRATION_ICONTROLLER=ON \
  -DTESTPERCALLSIGNREGISTRATION_ICONTROLLER_TESTS=ON
cmake --build build/ThunderNanoServices --target PerCallsignRegistrationIControllerTests -j"$(nproc)"
ctest --test-dir build/ThunderNanoServices --output-on-failure \
  -R PerCallsignRegistrationIControllerTests
```

That suite starts three instances of the IController test plugin (`Observer`, `PluginA`, and `PluginB`) and covers lifecycle filtering, duplicate registration, unregister behavior, and `StateControlStateChange` filtering.

## **IShell Plugin**

## JSON-RPC Methods

| Method | Parameters | Purpose |
|---|---|---|
| `TestPerCallsignRegistrationIShell.monitor` | `callsign` | Start monitoring one callsign or all plugins. |
| `TestPerCallsignRegistrationIShell.stopMonitoring` | `callsign` | Remove the matching monitor registration. |
| `TestPerCallsignRegistrationIShell.clearNotifications` | `{}` | Reset the count and last notification. |
| `TestPerCallsignRegistrationIShell.notificationCount` | `{}` | Return the recorded lifecycle notification count. |
| `TestPerCallsignRegistrationIShell.lastNotification` | `{}` | Return the latest notification as `Event:Callsign`. |

Events are recorded as `Activated:<callsign>`, `Deactivated:<callsign>`, or `Unavailable:<callsign>`.

## Callsign Selection

Monitor a single plugin with a non-empty callsign:

```json
"params": { "callsign": "PluginA" }
```

Monitor all plugins with `null`:

```json
"params": { "callsign": null }
```

Do not use `"params": {}` for `monitor` or `stopMonitoring`: the generated JSON-RPC parser requires the declared `callsign` member. Do not send `"callsign": ""` either. The QA plugin treats an empty value as the global selection, but `null` is the unambiguous request format.

## Multiple Callsigns

`monitor` accepts one callsign per request. To monitor multiple plugins, call it once for each callsign:

```text
monitor("PluginA")
monitor("PluginB")
```

The observer then receives lifecycle events for either callsign. Remove one subscription without affecting the other by calling `stopMonitoring` with that same callsign. Repeating `monitor` for an already monitored callsign returns an already-connected error.

## Global Registration Check

This validates existing all-plugin behavior. `null` is converted to an unset `Core::OptionalType<string>` before the plugin calls `IShell::Register`.

```bash
curl -s http://127.0.0.1:55555/jsonrpc \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":2,"method":"TestPerCallsignRegistrationIShell.clearNotifications","params":{}}'

curl -s http://127.0.0.1:55555/jsonrpc \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":3,"method":"TestPerCallsignRegistrationIShell.monitor","params":{"callsign":null}}'
```

Registration immediately produces an active-state snapshot for every currently active plugin. Therefore `notificationCount` is expected to be greater than zero, but its exact value depends on the environment.

Remove this global registration before testing callsign filtering:

```bash
curl -s http://127.0.0.1:55555/jsonrpc \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":4,"method":"TestPerCallsignRegistrationIShell.stopMonitoring","params":{"callsign":null}}'
```

## Per-Callsign Filtering Check

This procedure selects `PluginA` and uses `PluginB` as the control. Replace these placeholders with two lightweight, independently controllable callsigns configured in the QA environment.

1. Clear old results and monitor `PluginA` only:

```bash
curl -s http://127.0.0.1:55555/jsonrpc \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":5,"method":"TestPerCallsignRegistrationIShell.clearNotifications","params":{}}'

curl -s http://127.0.0.1:55555/jsonrpc \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":6,"method":"TestPerCallsignRegistrationIShell.monitor","params":{"callsign":"PluginA"}}'
```

2. An already active `PluginA` immediately creates an `Activated:PluginA` snapshot. Clear that snapshot before checking subsequent state changes:

```bash
curl -s http://127.0.0.1:55555/jsonrpc \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":7,"method":"TestPerCallsignRegistrationIShell.clearNotifications","params":{}}'
```

3. Deactivate the control, then the selected plugin:

```bash
curl -s -X POST http://127.0.0.1:55555/jsonrpc \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":8,"method":"Controller.1.deactivate","params":{"callsign":"PluginB"}}'

curl -s -X POST http://127.0.0.1:55555/jsonrpc \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":9,"method":"Controller.1.deactivate","params":{"callsign":"PluginA"}}'
```

4. Query the observed notifications:

```bash
curl -s http://127.0.0.1:55555/jsonrpc \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":10,"method":"TestPerCallsignRegistrationIShell.notificationCount","params":{}}'

curl -s http://127.0.0.1:55555/jsonrpc \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":11,"method":"TestPerCallsignRegistrationIShell.lastNotification","params":{}}'
```

Expected results:

```json
{"jsonrpc":"2.0","id":10,"result":1}
{"jsonrpc":"2.0","id":11,"result":"Deactivated:PluginA"}
```

The count of `1` proves `PluginB` was filtered out by Thunder's production `IShell` callsign registration while `PluginA` was delivered.

## Implementation Overview

`TestPerCallsignRegistrationIShell` implements both `PluginHost::IPlugin` and `PluginHost::IPlugin::INotification`.

1. During `Initialize()`, Thunder supplies the plugin's real `IShell` instance. The plugin keeps that instance and registers its QA JSON-RPC methods.
2. `monitor(callsign)` normalizes a null or empty JSON callsign to an unset `Core::OptionalType<string>`. It records the selection locally to reject duplicate monitor requests, then calls `_service->Register(this, selection)`.
3. Thunder's production `PluginServer` owns the registration and notification filtering. An unset selection subscribes the sink to all plugin lifecycle events; a non-empty selection subscribes it only to that exact callsign.
4. When Thunder delivers an `Activated`, `Deactivated`, or `Unavailable` callback, the plugin increments its notification count and stores the latest event as `Event:Callsign`.
5. `clearNotifications`, `notificationCount`, and `lastNotification` reset or expose those recorded callback results for QA assertions.
6. `stopMonitoring(callsign)` removes only the matching local selection and calls `_service->Unregister(this, selection)`. During `Deinitialize()`, the plugin unregisters every remaining selection before releasing `IShell`.

The plugin does not implement lifecycle filtering itself. Its local monitor list only tracks the subscriptions needed for duplicate detection and cleanup; the callsign filtering under test is performed by Thunder's `IShell`/`PluginServer` implementation.

## **IController Plugin**

`TestPerCallsignRegistrationIController` validates both notification paths exposed by `Exchange::Controller::ILifeTime`:

- `StateChange`, for normal plugin lifecycle transitions such as activate and deactivate;
- `StateControlStateChange`, for suspend and resume transitions generated by `IStateControl`.

The plugin's JSON-RPC controls call the production controller API internally:

```cpp
_controller->Register(this, callsign);
_controller->Unregister(this, callsign);
```

The observer must be active before calling its methods:

```bash
cmake -G Ninja -S ThunderNanoServices -B build/ThunderNanoServices \
  -DCMAKE_INSTALL_PREFIX="$PWD/install" \
  -DPLUGIN_TESTPERCALLSIGNREGISTRATION_ICONTROLLER=ON
cmake --build build/ThunderNanoServices --target install -j"$(nproc)"

curl -s -X POST http://127.0.0.1:55555/jsonrpc \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":101,"method":"Controller.1.activate","params":{"callsign":"TestPerCallsignRegistrationIController"}}'
```

The IController JSON-RPC methods are:

| Method | Parameters | Purpose |
|---|---|---|
| `TestPerCallsignRegistrationIController.monitor` | `callsign` | Register through `IController` for one callsign or all callsigns. |
| `TestPerCallsignRegistrationIController.stopMonitoring` | `callsign` | Remove the matching controller registration. |
| `TestPerCallsignRegistrationIController.clearNotifications` | `{}` | Reset the count and latest notification. |
| `TestPerCallsignRegistrationIController.notificationCount` | `{}` | Return the recorded notification count. |
| `TestPerCallsignRegistrationIController.lastNotification` | `{}` | Return the latest formatted notification. |

Use `"callsign": null` for all plugins, or a non-empty callsign for a specific plugin. As with the IShell plugin, `monitor` and `stopMonitoring` require the `callsign` member; use `null`, not an empty `params` object.

### IController Lifecycle Test

Replace `PluginA` and `PluginB` with two real, independently controllable configured callsigns. `PluginA` is the selected callsign and `PluginB` is the control callsign.

```bash
# Clear previous callbacks.
curl -s http://127.0.0.1:55555/jsonrpc \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":102,"method":"TestPerCallsignRegistrationIController.clearNotifications","params":{}}'

# Register only for PluginA. If PluginA is already active, this also records
# its initial StateChange snapshot (and StateControlStateChange if supported).
curl -s http://127.0.0.1:55555/jsonrpc \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":103,"method":"TestPerCallsignRegistrationIController.monitor","params":{"callsign":"PluginA"}}'

# Remove the registration snapshot before testing transitions.
curl -s http://127.0.0.1:55555/jsonrpc \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":104,"method":"TestPerCallsignRegistrationIController.clearNotifications","params":{}}'

# PluginB must not be delivered to the PluginA-specific registration.
curl -s -X POST http://127.0.0.1:55555/jsonrpc \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":105,"method":"Controller.1.deactivate","params":{"callsign":"PluginB"}}'

# PluginA must be delivered.
curl -s -X POST http://127.0.0.1:55555/jsonrpc \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":106,"method":"Controller.1.deactivate","params":{"callsign":"PluginA"}}'

curl -s http://127.0.0.1:55555/jsonrpc \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":107,"method":"TestPerCallsignRegistrationIController.notificationCount","params":{}}'

curl -s http://127.0.0.1:55555/jsonrpc \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":108,"method":"TestPerCallsignRegistrationIController.lastNotification","params":{}}'
```

Expected result after clearing the registration snapshot:

```json
{"jsonrpc":"2.0","id":107,"result":1}
{"jsonrpc":"2.0","id":108,"result":"StateChange:PluginA:DEACTIVATED:REQUESTED"}
```

### IController State-Control Test

Use the existing ThunderNanoServices `TestStateControl` plugin as the target. It is used because it explicitly implements `PluginHost::IStateControl` and provides deterministic suspend/resume transitions. Those transitions cause Thunder to forward `StateControlStateChange` notifications through `IController`; a generic plugin that does not implement `IStateControl` cannot exercise this callback path.

Build and activate `TestStateControl` before running this section:

```bash
cmake -G Ninja -S ThunderNanoServices -B build/ThunderNanoServices \
  -DCMAKE_INSTALL_PREFIX="$PWD/install" \
  -DPLUGIN_TESTSTATECONTROL=ON \
  -DPLUGIN_TESTPERCALLSIGNREGISTRATION_ICONTROLLER=ON
cmake --build build/ThunderNanoServices --target install -j"$(nproc)"

curl -s -X POST http://127.0.0.1:55555/jsonrpc \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":109,"method":"Controller.1.activate","params":{"callsign":"TestStateControl"}}'
```

When monitoring an already active `TestStateControl`, registration can produce two initial callbacks: `StateChange:TestStateControl:ACTIVATED:<reason>` and `StateControlStateChange:TestStateControl:RESUMED`. Always clear after `monitor`; notification counts are cumulative until `clearNotifications` is called.

```bash
curl -s http://127.0.0.1:55555/jsonrpc \
```

## IController Implementation Overview

`TestPerCallsignRegistrationIController` implements `Exchange::Controller::ILifeTime::INotification`, so it can receive the callbacks produced by Thunder's controller. Its QA JSON-RPC methods are only test controls; the filtering is performed by the production `Controller` implementation.

1. During `Initialize()`, the plugin obtains the controller's `Exchange::Controller::ILifeTime` interface through `QueryInterfaceByCallsign("")`. The empty query callsign means the controller itself, not a plugin instance.
2. `monitor(callsign)` normalizes `null` or an empty callsign to an unset `Core::OptionalType<string>`, then calls `_controller->Register(this, selection)`. An unset selection means all plugin callsigns; a set selection means one exact callsign.
3. When Thunder changes a plugin lifecycle state, the production path is `PluginServer -> Controller::NotifyStateChange -> StateChange(...)`. The plugin records values such as `StateChange:PluginA:DEACTIVATED:REQUESTED`.
4. When a plugin implementing `IStateControl` is suspended or resumed, the production path is `IStateControl -> PluginServer::StateControlStateChange -> Controller::NotifyStateControlStateChange -> StateControlStateChange(...)`. The `TestStateControl` plugin is used because it provides this real source event deterministically.
5. A callsign-specific registration can immediately produce an initial `StateChange` snapshot and, when the target supports `IStateControl`, an initial `StateControlStateChange` snapshot. Clear notifications after registration before measuring later transitions.
6. `notificationCount` and `lastNotification` expose the callbacks recorded by the observer. The count is cumulative until `clearNotifications` is called; `lastNotification` returns only the most recent callback.
7. `stopMonitoring(callsign)` calls `_controller->Unregister(this, selection)`. During `Deinitialize()`, the plugin unregisters every remaining controller selection and releases its controller and state-control resources.

The plugin's local monitor list is used only for duplicate detection, rollback after a failed controller registration, and cleanup. It does not perform callsign filtering; that behavior is exercised in Thunder's production `Controller` code.
